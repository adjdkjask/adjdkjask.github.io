✨ What This Tool Does for You

When you ask Claude Code to make a change to a file, it usually reports back with a "diff" — a description of what it removed and what it added. Diffs are wonderful in theory, but the standard version stacks everything into a single tall column. Removed lines sit above added lines. When a change is large, your eyes have to jump up and down constantly to match what disappeared with what replaced it.

cc-split-diff-view fixes this by drawing changes in two columns, right next to each other:

  • The left column shows the lines as they were before the change.
  • The right column shows the lines as they are after the change.
  • Matching lines stay level with each other, so you can compare them at a glance.

Think of it like comparing two versions of a printed page side by side on a desk, rather than flipping back and forth between them. For anyone reviewing work, learning what a tool did, or just double-checking that nothing important was deleted, this layout is dramatically easier to read.

🧭 Using It Day to Day

There is nothing new to learn. You keep working exactly as you always have: you describe a change you want, Claude Code makes it, and the diff appears. The only difference is the shape of what you see.

A few habits make the two-column view even more useful:

  • Widen before you read. Stretch the window horizontally rather than vertically. Wider is better here.
  • Read left to right, line by line. Because matching lines are aligned, you can scan across a row to see exactly what shifted.
  • Check the outer edges. Markers on the far left and far right tell you which lines were removed and which were added.
  • Scroll slowly on big changes. Large edits are where the two-column layout saves the most time, but only if you read one row at a time.

🔄 How Edit and Write Changes Are Shown

Claude Code changes files in two main ways, and this tool handles both.

Edits

An edit means part of a file was changed. You will see the original wording on the left and the replacement wording on the right, lined up row by row. Unchanged lines appear on both sides in the same position, which gives you a stable reference point as you read down the page.

Writes

A write means a whole file was created or fully replaced. Here you will typically see an empty or minimal left column and the full new content on the right. This makes new files instantly recognisable.

🛠️ Common Questions and Fixes

The view still looks like one column

Close your Claude Code session completely and start it again. Then make one more small change to a file and check the result.

The columns look squashed

Your window is too narrow. Drag the right edge of the window outward, or reduce the text size in your terminal settings. Both give the layout more room.

The text is hard to read

Adjust your terminal's font size and colour theme. The two-column layout respects whatever appearance settings you already have, so a theme that is comfortable for you will stay comfortable here.
